# Audit UX Lazisnu — 2026-07-20

> **Status**: VALID — baseline resmi pertama berdasarkan screenshot aktual aplikasi web dan mobile.
>
> Audit ini menggantikan laporan 2026-07-18 yang dinyatakan tidak valid. Temuan di sini boleh dipakai sebagai baseline resmi untuk prioritas redesign.

---

## 1. Ringkasan Eksekutif

Audit siklus pertama yang valid ini didasarkan pada observasi langsung terhadap 23 screenshot aplikasi aktual: 10 halaman web dashboard dan 13 layar mobile Android. Secara keseluruhan, fondasi visual aplikasi sudah kuat — palet warna "Earthy & Premium" (hijau gelap, krem/beige, aksen emas) diterapkan konsisten di kedua platform. Namun ditemukan sejumlah masalah yang menghambat efisiensi kerja lapangan: **alur utama scan QR mobile belum memberikan CTA langsung dari daftar tugas**, hierarki informasi di header web tidak konsisten antara layar dengan sidebar dan tanpa sidebar, serta beberapa state kritis (gagal kirim, data tidak lengkap) belum mendapat visual treatment yang cukup mencolok. Terdapat 14 pain point yang teridentifikasi dari evaluasi heuristik, dengan 2 di antaranya berseveritas 3 (major) dan tidak ada yang mencapai tingkat 4 (catastrophic).

## 4. Perbandingan Konsistensi Web vs Native

| Area | Observasi Web | Observasi Mobile | Penilaian Konsistensi |
|---|---|---|---|
| **Identitas visual / palet warna** | Hijau gelap (#1a3c2a-ish), aksen emas/krem, dark mode | Hijau gelap gradient, aksen emas/krem, light mode di form | ⚠️ **Sebagian konsisten** — palet serupa tapi web full dark, mobile mix dark header + light body. Perbedaan ini wajar untuk platform berbeda, namun perlu dijaga agar komponen bersama (badge, tombol) tetap satu bahasa warna. |
| **Bottom navigation vs Sidebar** | Web: sidebar kiri persistent dengan 9 item | Mobile: bottom nav 5 tab (Beranda, Tugas, Scan, Riwayat, Profil) | ✅ **Sesuai platform** — pendekatan navigasi sudah tepat untuk masing-masing platform. |
| **Label dan terminologi** | Menggunakan campuran Bahasa Indonesia (sidebar) dan Inggris (breadcrumb/URL) | Konsisten Bahasa Indonesia di seluruh layar | ❌ **Tidak konsisten** — mobile lebih baik. Web perlu menyeragamkan bahasa di semua lapisan UI. |
| **Status badge** | Badge status: "ASSIGNED" (oranye), "AKTIF" (hijau), "NON-AKTIF" (abu) | Badge status: "Belum" (krem), "Selesai" (hijau), "Terkoreksi" (krem), "Gagal Terkirim" (merah), "Tersimpan" (hijau muda) | ⚠️ **Terminologi berbeda untuk konsep serupa** — web menggunakan bahasa sistem (ASSIGNED), mobile menggunakan bahasa operasional (Belum). | **Hierarki aksi primer** | Tombol primer (Tambah, Tugaskan) muncul di kanan atas — ukuran konsisten | Tombol primer ada di form (Simpan) dan di success screen (Scan QR Baru, Kembali ke Beranda) — hierarki cukup jelas di layar sukses, kurang jelas di layar tugas | ⚠️ **Mobile kurang tegas di entry point tugas** — perlu CTA scan di kartu tugas (lihat UX-M01). |

## 5. Rekomendasi Arah Redesign

> Catatan: Ini adalah arah high-level, bukan solusi UI final. Eksekusi desain adalah tanggung jawab Product Designer.

### 5.1 Prioritas Tinggi (Severity 3)

1. **Perkuat CTA alur utama di mobile** (UX-M01, UX-M06)
   - Setiap kartu tugas harus memiliki satu aksi primer yang jelas: "Scan QR" atau "Mulai".
   - Pesan error harus ditulis dalam bahasa tindakan, bukan kode sistem.

2. **Tambahkan grouping navigasi di sidebar web** (UX-W02)
   - Pemisahan visual antara menu operasional harian vs menu administratif akan membantu admin baru dan admin yang jarang mengakses modul teknis.

3. **Standarkan validasi input alasan koreksi** (UX-W08)
   - Tanpa validasi bermakna, jejak audit koreksi tidak dapat dipercaya — ini mempengaruhi akuntabilitas finansial organisasi.

### 5.2 Prioritas Menengah (Severity 2)

4. **Konsistensi bahasa di semua layer UI web** (UX-W04)
   - Breadcrumb, URL slug, dan label menu perlu seragam dalam satu bahasa (Bahasa Indonesia).

5. **Perbaiki data visualization grafik Overview** (UX-W05)
   - Grafik dengan satu outlier dominan tidak memberikan insight yang berguna.

6. **Tambahkan filter & search di Riwayat mobile dan Re-submit web** (UX-M04, UX-W07)
   - Kedua layar ini akan semakin susah dipindai seiring bertambahnya volume data.

7. **Perkuat visual badge "Gagal Terkirim" di mobile** (UX-M05)
   - State kritis butuh pre-attentive visual treatment, bukan sekadar warna teks.

8. **Perkaya informasi Profil Petugas** (UX-M07)
   - Konteks kerja (ranting, zona) dan statistik bulanan penting untuk orientasi petugas.

9. **Perbaiki state loading di WA Monitor** (UX-W06)
   - Bedakan loading, empty state, dan error secara visual.

### 5.3 Prioritas Rendah (Severity 1–2, Quick Win)

10. **Header identitas produk selalu tampil saat sidebar collapsed** (UX-W01)
    - Quick win visual yang memperkuat orientasi tanpa perubahan besar.

11. **Sticky CTA di form Input Penjemputan** (UX-M03)
    - Teknikal kecil, namun mengurangi friction di momen kritis paling sering dilakukan petugas.

12. **Diferensiasi hierarki tombol di layar Scan QR** (UX-M02)
    - Perjelas fallback path: "Tempel Kode" vs "Pilih Gambar QR".
