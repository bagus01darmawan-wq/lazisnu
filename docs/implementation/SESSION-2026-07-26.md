## 1. WA — Web Dashboard

### WA1 — Middleware Role Guard
**Akar:** Verifikasi bahwa middleware hanya menggunakan 4 role valid pasca-pembersihan Sub-bab 02.

**Hasil:** Middleware [middleware.ts](apps/web/src/middleware.ts) sudah benar — hanya mengecek `ADMIN_KECAMATAN`, `ADMIN_RANTING`, `BENDAHARA`, `PETUGAS`. Tidak ada referensi `ADMIN_PUSAT` atau `ADMIN_KABUPATEN`. **Tidak ada perubahan kode.**

### WA2 — Cookie maxAge 15 Menit
**Akar:** Cookie `lazisnu_token` `maxAge` = 1 hari, tapi access token JWT TTL = 15 menit. Cookie hidup lebih lama dari token → middleware verifikasi cookie basi gagal → user di-redirect ke login meski refresh token masih valid.

**Solusi:** Sinkronkan `maxAge` cookie dengan TTL access token = **15 menit (900 detik)**.

**File yang dimodifikasi:**
| File | Perubahan |
|------|-----------|
| [login/route.ts](apps/web/src/app/api/auth/login/route.ts) | `maxAge: 60*60*24` → `maxAge: 60*15` |
| [refresh/route.ts](apps/web/src/app/api/auth/refresh/route.ts) | `maxAge: 60*60*24` → `maxAge: 60*15` |
| [lib/auth.ts](apps/web/src/lib/auth.ts) | `expires: 1` (hari) → `expires: new Date(Date.now() + 15*60*1000)` |

### WA3 — Zod ke Dependencies
**Akar:** `zod` di `devDependencies`, tapi dipakai runtime di 5 halaman production (`login`, `assignments`, `cans`, `users`, `users/[id]`). Production build (`pnpm install --prod`) tidak meng-install `devDependencies` → risiko `Cannot find module 'zod'`.

**Solusi:** Pindahkan `zod` dari `devDependencies` ke `dependencies` di [web/package.json](apps/web/package.json).

### WB1 — deviceId di Web Client
**Akar:** Backend Sub-bab 04 sudah mendukung multi-device session per `{userId}:{deviceId}`, tapi web dashboard tidak pernah mengirim `device_id`. Akibatnya backend tidak bisa membedakan sesi per browser/device.

**Solusi:** Generate UUID sekali, persist di **sessionStorage** (untuk client component) + **cookie** (untuk server route handler).

**File yang dibuat/dimodifikasi:**
| File | Perubahan |
|------|-----------|
| [lib/deviceId.ts](apps/web/src/lib/deviceId.ts) | BARU — `getOrCreateDeviceId()`: generate UUID, simpan ke sessionStorage + cookie 365 hari |
| [login/page.tsx](apps/web/src/app/(auth)/login/page.tsx) | `getOrCreateDeviceId()` sebelum POST login |
| [login/route.ts](apps/web/src/app/api/auth/login/route.ts) | Terima `device_id` dari body → teruskan ke backend + set cookie |
| [refresh/route.ts](apps/web/src/app/api/auth/refresh/route.ts) | Baca `device_id` dari cookie → teruskan ke backend |

**Akar:** Sama dengan WB1 — mobile app belum mengirim `device_id` di endpoint auth.

**Solusi:** `getOrCreateDeviceId()` + `getDeviceLabel()` di [api.ts](apps/mobile/src/services/api.ts). Device ID disimpan permanen di MMKV (tidak re-generate saat restart).

## 3. MB–ME — Biometrik Mobile (D-09: Opsional)

### MB — Biometric Service
**Akar:** Refresh token sudah ada di MMKV, tapi tidak ada cara aman menggunakannya untuk login cepat tanpa menyimpan password (yang tidak boleh).

**Solusi:** Biometrik sebagai **gatekeeper lokal** — sidik jari membuka akses ke refresh token di Android Keystore / iOS Keychain. Server tetap otoritas penuh.

**File:** [biometric.ts](apps/mobile/src/services/biometric.ts) (BARU)

| Fungsi | Tugas |
|--------|-------|
| `isBiometricAvailable()` | Cek HP support biometrik |
| `getBiometryType()` | Jenis: "Sidik Jari" / "Touch ID" / "Face ID" |
| `enableBiometric(token)` | Simpan refresh token ke Keystore (biometrik-protected) |
| `getTokenWithBiometric()` | Prompt sidik jari → kembalikan refresh token |
| `updateBiometricToken(token)` | Timpa token lama dengan baru (rotasi) |
| `disableBiometric()` | Hapus token dari Keystore |

### MC — Auth Store Biometric Actions
**Akar:** `biometric.ts` tidak terhubung ke UI. Butuh store sebagai jembatan.

**Solusi:** Tiga aksi baru + state `biometricEnabled` (persist ke MMKV) di [useAuthStore.ts](apps/mobile/src/stores/useAuthStore.ts):

| Aksi | Alur |
|------|------|
| `enableBiometric()` | Cek support → ambil refresh token → simpan Keystore |
| `loginWithBiometric()` | Sidik jari → refresh ke server → rotasi token Keystore → set state user |
| `disableBiometric()` | Hapus Keystore + hapus flag MMKV |

### MD — Login Screen Biometric Button
**Akar:** LoginScreen hanya punya mode password dan OTP.

**Solusi:** Tombol "Masuk dengan Sidik Jari" (`icon={'fingerprint'}`, `variant={'outline'}`) — **hanya muncul jika `biometricEnabled === true`** di [LoginScreen.tsx](apps/mobile/src/screens/LoginScreen.tsx).

### ME — Profile Screen Biometric Toggle
**Akar:** Tidak ada tempat mengaktifkan/menonaktifkan biometrik.

**Solusi:** Section baru "Keamanan Biometrik" di [ProfileScreen.tsx](apps/mobile/src/screens/ProfileScreen.tsx):
- Switch toggle On/Off
- Label jenis biometrik ("Sidik Jari" / "Touch ID")
- Section tidak muncul jika HP tidak support biometrik

## 4. MF — D-01: OTP via WhatsApp (Opsi A)

**Akar (Sub-bab 06 P0-1):** OTP di-generate dan disimpan Redis tapi **tidak pernah dikirim**. User minta OTP → tidak dapat WA.

**Solusi:**

**1. `sendOtpMessage()` di [whatsapp.ts](apps/backend/src/services/whatsapp.ts)**
- Kirim via WA API (Fonnte/Meta) — **dipanggil langsung**, bukan via queue (OTP TTL 5 menit)
- OTP **TIDAK PERNAH di-log** — hanya metadata (nomor HP dimasking + message_id WA)
- Dry-run di dev mode (WA credentials kosong)

**2. Panggil di [auth.ts](apps/backend/src/routes/auth.ts):**
- Setelah `generateAndStore` → panggil `sendOtpMessage(phone, otp)`
- Jika `WA_SEND_FAILED` → return 502, jangan klaim terkirim

## 5. MG — Unit Test Biometric

**Akar:** Biometric service perlu diverifikasi — kode keamanan, 4 skenario edge case.

**Solusi:** [biometric.test.ts](apps/mobile/__tests__/services/biometric.test.ts) (BARU) — 4 skenario:
1. **Enable** → token di Keystore dengan `accessControl: BIOMETRY_ANY`
2. **Rotasi** → `updateBiometricToken()` menimpa token lama
3. **Toggle off** → `disableBiometric()` → Keystore kosong
4. **Revoke** → `getTokenWithBiometric()` return null setelah disable

**Mock Keychain diupdate:** +`getSupportedBiometryType`, +`ACCESS_CONTROL`, +`BIOMETRY_TYPE`, +`__setBiometryType`.
