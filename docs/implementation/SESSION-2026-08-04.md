## 4. Biometrik — `react-native-keychain` 8.2.0 → 10.0.0 (PR #33)

### 4.1 Gejala Awal

- Toggle biometrik ON gagal tanpa prompt: "perangkat tidak mendukung biometrik" — padahal HP punya fingerprint + lock screen PIN.
- Diagnosa: `setGenericPassword` dengan `accessControl: BIOMETRY_ANY` gagal diam-diam (bug 8.2.0 pembuatan key biometrik di Android Keystore; prompt tidak muncul).

### 4.2 Perbaikan

- Upgrade `react-native-keychain` **8.2.0 → 10.0.0** (v9 = rewrite Kotlin + fix prompt biometrik; v9.2.1 fix decrypt entry lama; v10 minSdk 23 cocok).
- `secureKey.ts`: hapus `storage: AES_CBC` (deprecated; v10 default AES-GCM). Entry lama tetap terbaca (fix v9.2.3).
- `biometric.ts`: `authenticationPrompt` saat enable + `console.warn` error native untuk diagnosa.
- `eas.json`: profile baru **`internal-prod`** (APK + API_URL production) untuk sideload via EAS.
- Hasil: **toggle biometrik ON bekerja** di APK pertama (prompt sidik jari muncul).

### 4.3 Bug Kedua: Login Biometrik Setelah Logout Gagal

- Logout memanggil `POST /auth/logout` yang me-revoke refresh token device (`revokeDeviceSession` + `revokedAt`) — token yang sama tersimpan di Keychain untuk biometrik → selalu `REFRESH_REVOKED`.

### 4.4 PR #34 — Logout Lokal Saat Biometrik Aktif

- `useAuthStore.logout`: jika `biometricEnabled` → logout lokal saja (bersihkan state app, tanpa revoke server). Sesi device tetap hidup untuk re-login sidik jari.
- Jika biometrik nonaktif → perilaku lama (revoke server) tetap.
- Pencabutan sesi tetap bisa dari web (logout semua perangkat) → `REFRESH_REVOKED` → biometrik nonaktif otomatis (alur sudah ada, useAuthStore 449-457).

## 5. PR #35 — CI Path-Filtering (Iterasi Lebih Cepat)

### 5.1 Masalah

- Setiap merge ke main memicu CI penuh (build image backend+web+staging + deploy staging, ±15-20 mnt) bahkan untuk perubahan kecil mobile/docs.

### 5.2 Solusi

- Job `changes` (dorny/paths-filter v3) → output `backend` / `web` / `mobile` / `infra`.
- `build-image` + `deploy-staging`: skip jika hanya `mobile` yang berubah; `lint-and-typecheck` step backend/mobile gated per-area.
- **docs-only commit** → workflow skip total (`paths-ignore: docs/**, *.md`).
- Tag push / `workflow_dispatch` → CI penuh tanpa filter (jalur deploy production aman).
- Tidak ada branch protection di repo → skip CI tidak memblokir merge.

## 6. PR #36 — Fix `user_sessions.device_id` + Mock Vector-Icons (Test Windows)

### 6.1 Backend — `device_id` Terisi

- `sessionService.createSession` menerima `deviceId` dan menyimpannya ke kolom.
- `login` & `verify-otp` kirim `tokens.did` (konsisten dengan Redis key); `refresh` kirim `decoded.did`.
- Integration test regresi (login dengan `device_id` → kolom terisi): 20/20 PASS.

### 6.2 Mobile — 3 Suite Test UI Gagal di Windows

- **Akar masalah**: `react-native-vector-icons` tidak mendeklarasikan `react` sebagai dependency/peer → di pnpm resolve jatuh ke hoisting `.pnpm/node_modules/react` = **react@19.2.4** (dipakai `apps/web` — Next 16), sedangkan react-test-renderer memakai react@18.2.0 → elemen React 19 ditolak renderer React 18: "Objects are not valid as a React child" pada tiap render `<Icon>`. Hanya muncul di Windows (layout node_modules pnpm beda antar platform; CI Linux lolos).
- **Fix**: mock `react-native-vector-icons/MaterialCommunityIcons` (render `<Text>` + testID) di `__mocks__/` — pola standar Jest; app runtime tidak terpengaruh (Metro resolve react 18 dari apps/mobile).
- Hasil: **10 suites / 73 test mobile PASS lokal di Windows** (sebelumnya 20 gagal).
