## 3. 08-B2 / 07-E2-3 — Test Restore Backup Pertama

### Root Cause (Attempt 1 & 2 — Gagal)
- `pg_dump` tanpa flag `--schema=public` → dump semua schema Supabase internal
- Restore gagal karena schema (`auth`, `drizzle`, dll) sudah ada di staging → `CREATE TABLE` error → `COPY` data tidak dieksekusi

### Fix: Perbarui `scripts/backup.sh`

```bash
# Sebelum:
pg_dump "$DIRECT_URL"

# Sesudah:
pg_dump \
  --schema=public \
  --no-owner \
  --no-acl \
  --clean \
  --if-exists \
  "$DIRECT_URL"
```

- `--schema=public` → hanya schema aplikasi
- `--no-owner --no-acl` → tidak dump permission Supabase
- `--clean --if-exists` → tambah `DROP TABLE IF EXISTS` → restore idempotent ke DB yang sudah punya schema

## 4. 07-G3-5 — Backup Control API E2E

### Root Cause (Issue 1): Route 404
- Container backend masih pakai image lama (sebelum `backup.ts` di-commit)
- Fix: `docker compose build backend && docker compose up -d --no-deps backend`
- Konfirmasi: `curl https://api.lazisnu.site/v1/admin/backup/status` → **401** (route ada, auth diperlukan)

### Root Cause (Issue 2): `POST /backup/stop` → HTTP 500

```
ERROR:  Gagal menonaktifkan backup
```

- Container mount **file** bukan **direktori**: `./backup-active:/app/backup-active`
- Docker file bind-mount tidak bisa di-`unlink()` dari dalam container
- `unlinkSync('/app/backup-active')` → Permission Denied / EISDIR

### Fix: Ganti ke Directory Mount

```yaml
# docker-compose.yml — sebelum:
volumes:
  - ./backup-active:/app/backup-active
environment:
  - BACKUP_FLAG_PATH=/app/backup-active

# Sesudah:
volumes:
  - ./backup-data:/app/backup-data
environment:
  - BACKUP_FLAG_PATH=/app/backup-data/active
```

- Buat direktori `/opt/lazisnu/backup-data/` di VM
- Migrate flag: `cp backup-active backup-data/active`
- Update `scripts/backup.sh`: `FLAG_FILE="/opt/lazisnu/backup-data/active"`
- Recreate backend container

## 3. Temuan Sesi Ini (Backlog Baru)

### 3.1 Password Admin Grafana tidak bisa di-reset via CLI

- **Gejala**: `docker exec lazisnu-grafana-1 grafana cli admin reset-admin-password admin` exit 0 tapi response `401 Unauthorized` saat test Basic auth `admin:admin`
- **Root cause**: env `GF_SECURITY_ADMIN_PASSWORD=admin` di `docker inspect` ada, tapi password sudah di-hash dengan salt berbeda saat provisioning awal (mungkin di-set via API setelah container start, atau dari `grafana_data` volume)
- **Dampak**: tidak bisa akses API Grafana yang butuh admin auth (cari dashboard by tag, hapus dashboard, dll)
- **Rekomendasi**:
  - Cek apakah ada service account token / API key tersimpan di `grafana-data/` volume
  - Atau stop container → `rm -rf grafana-data/*` → start ulang (akan re-init dengan password `admin` dari env)
  - Atau set password baru via DB langsung (Grafana pakai sqlite di `grafana-data/grafana.db`)
- **Prioritas**: Rendah — semua verifikasi sudah bisa via Prometheus API (tidak butuh login Grafana untuk monitoring)

### 3.2 HTTP Request Metrics Tidak Terexpose

- **Gejala**: query `http_request_duration_seconds_count` dan `http_requests_total` ke Prometheus → `(no data)`
- **Dampak**: alert rule `HighHttpErrorRate` (5xx > 5% selama 2 menit) tidak akan pernah firing, karena tidak ada data HTTP request
- **Root cause**: nama metrik HTTP di backend mungkin berbeda (cek `apps/backend/src/metrics/` atau `apps/backend/src/app.ts` tempat `prom-client` di-register)
- **Rekomendasi**:
  1. Cek endpoint `/metrics` raw output: `curl -s https://api.lazisnu.site/metrics | grep -iE 'http|request'`
